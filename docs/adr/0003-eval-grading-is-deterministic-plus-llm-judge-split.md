# Eval grading splits deterministic checks from LLM-as-judge rubric grading

The four pipeline skills (to-vision, to-pitch, to-roadmap, to-milestone) are HITL — the "founder" side of each conversation is a human, so an eval scenario's output can't be checked with classic input/output assertions. We considered human-only review (too slow/expensive to run repeatedly) and fully automated deterministic checks alone (too weak to catch content failures like a slogan disguised as a vision). Instead, each eval scenario's grade splits in two: deterministic checks for mechanical compliance (approval-marker presence per #9, composition-rule compliance, artifact-backend fields per #7), and LLM-as-judge grading against a per-skill rubric for content quality. Human review is reserved for spot-checks — triggered when the judge flags low confidence, and mandatory on the cooperative/sharp-founder scenario before a skill is eval-complete — rather than being the default grading path.

Decided on [Evaluation framework for the four skills (#12)](https://github.com/98kb/skills/issues/12), a ticket on [Milestone map: to-vision / to-pitch / to-roadmap / to-milestone skill design (#1)](https://github.com/98kb/skills/issues/1).
