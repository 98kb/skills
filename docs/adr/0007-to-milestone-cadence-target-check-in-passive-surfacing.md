# to-milestone gate checks fire on a hybrid cadence — a stored Target Check-in plus passive surfacing, not push notifications or pure pull

`to-milestone`'s decision taxonomy (advance/persevere/pivot/stop) said what happens once a gate check runs, but nothing said *when* one fires. As scoped, `to-milestone` was purely pull-based — nothing prompted a check unless the founder invoked it, unlike Shape Up's six-week clock or Amazon's WBR/OKR cadences, which enforce review independent of anyone remembering to look. For a solo founder running multiple parallel projects, that gap lets "persevere" silently become "forgotten for months."

No notification/platform layer exists in this skills-only phase, so a true push-based cadence isn't buildable yet. Instead: every Move gets a **Target Check-in** date (5th Move field, amending [ADR 0006](./0006-to-roadmap-artifact-schema-strategic-frame-replaces-wedge.md)'s 4-field list) — computed once as activation date plus an Appetite-derived interval, and recomputed the same way on every persevere Verdict so persevere doesn't leave a Move reading as instantly overdue. `to-roadmap`'s Re-entry session, `to-milestone`, and `/wayfinder` each check on invocation whether the active Move's Target Check-in has passed and surface it before doing anything else — a passive, computed-on-demand nudge rather than a stored "already reminded" flag. `to-vision` and `to-pitch` are excluded: they have no natural reach into a specific roadmap's Moves under the existing one-hop-upstream/downstream-by-listing-children convention, and building that reach isn't justified here. A founder can still gate-check earlier than the Target Check-in on a decisive signal — no separate mechanism is needed for that; it's an ordinary `to-milestone` invocation, with earliness visible after the fact by comparing the resulting gate-check date to the snapshotted Target Check-in. The Milestone artifact schema (amending [#36](https://github.com/98kb/skills/issues/36)'s 7 fields to 8) snapshots that Target Check-in alongside its existing gate-check date for exactly this comparison.

Considered and rejected: pure founder-initiated-only with no compensation (the status quo gap this ticket closes — accepted as inadequate given the stated forgetting failure mode); deferring the whole question to a future notification/platform layer (rejected — a stored date plus on-invocation surfacing is buildable now, at effectively no cost, without waiting on infrastructure that doesn't exist); a raw "Activated At" timestamp with the check-in date derived at read time (rejected — inconsistent with the schema's existing minimalism, where Evidence Threshold is itself a stored, ready-to-compare value rather than derived from more primitive fields on every read).

Decided on [to-milestone: cadence — when does the gate check actually fire? (#42)](https://github.com/98kb/skills/issues/42), a cross-cutting ticket on [Milestone map: to-vision / to-pitch / to-roadmap / to-milestone skill design (#1)](https://github.com/98kb/skills/issues/1).
