# The open-questions register is adjacent to the always-loaded tier, not in it — and the byte tripwire has no shed action

[ADR 0011](0011-conditional-go-the-stance-record-is-the-delta-between-stated-and-evidenced.md) turned the open-questions register from a leftover bin into a product of position-writing: every position emits a **residue**, the residue is reopened as a register entry, and the seed sitting produces nothing else. [ADR 0012](0012-to-stance-mechanisms-computed-over-declared-and-approval-is-authorship.md) then adopted a 25KB tripwire on the always-loaded tier and parked its trip action here, on the reasoning that "the only sheddable mass in the always-loaded tier is what is not routing lines."

The [`jian-yang.md` re-cut](https://github.com/98kb/skills/tree/prototype/stance-recut/prototypes/stance-recut) measured the consequence at one accrual sitting: 2 routing lines against a coverage statement four lines long, because there were more open questions than positions — *"the always-loaded tier is dominated by a list of what the record does not cover. Nobody designed for that."*

Four answers were on the table: load the register fully, route it like positions, summarise it, or drop it from the tier. **None is adopted.** The tier boundary cuts through a register entry rather than around it, and what remains on the founder-facing side turns out not to need residency at all.

## A register entry is two things with opposite standing

The four candidates all treat "the register" as one unit that is either loaded or not. It is not one unit. A register entry holds a **question** — *what would you give up in order to move faster?* — which is a statement of silence and carries no claim; and a **disposition on file** — *refuses all three, as a class* — which is a standing disposition no episode reaches.

That second thing is what ADR 0011 quarantined. Its residue rule is stated for a position, but the rule it states is about a kind of material rather than a location: an unevidenced absolute with no routing line cannot be retrieved, so it cannot be projected onto, and Fagerlin & Schneider's sharpest mechanism is that vagueness is not neutral — it "exacerbates [interpreters'] natural tendency to read documents in light of their own preferences." A `residue`-origin register entry's disposition on file **is** a residue, in a second file. The other two origins carry material of exactly the same kind.

**So the quarantine is one rule with two locations, and this ADR states it as one**: *a stated disposition that no episode reaches is recorded and never retrievable, wherever it sits.* Residue and disposition-on-file are its two occurrences, not two rules that happen to agree.

This disposes of two of the four candidates outright. **Fully loaded** puts quarantined material in every reader's context window permanently, which is the strongest version of the thing the quarantine exists to stop. **Routed like positions** is worse, and dies twice over: a routing line would retrieve by the back door precisely what the quarantine removed from the retrieval path, and a register line competes lexically with position lines on every position, manufacturing as standard behaviour the two-match case that [Two routing lines bear on one question (#116)](https://github.com/98kb/skills/issues/116) is open on because nobody knows what unranked retrieval does with it. The second kill is the durable one: it survives whatever #116 decides, because a routing line is the record's assertion that it **can** answer and a register entry is its admission that it cannot. Same surface, opposite speech act.

## The remaining question is what the *questions* are for, and the answer is not reading

With dispositions quarantined, what could sit in the tier is the bare list of open questions. The case for it was negative discovery at read time — the ticket priced dropping the register as *"gives up the negative-discovery mechanism at read time, which is currently the only one there is."*

**That price is false, and ADR 0012 already says so in as many words**: "the absence of an index line *is* the computable no-match," reached independently from the retrieval side and the archival side and called this map's doubly-confirmed convergence. Negative discovery at read time is delivered by the empty routing table. An enumerated register adds only the *silent-by-record* versus *silent-by-omission* distinction, on top of a no-match that has already fired — and a reader's action is identical either way, because the disposition is unretrievable in both cases and the never-an-authority constraint sends them to a human regardless.

There is exactly one consumer with a differential action, and it is not a reader. ADR 0012's **`observed` origin** has an agent appending a register entry at the moment of a no-match. If the question is already registered, that agent appends a dated occurrence to the existing entry instead of opening a duplicate — which turns repeat hits into a countable signal for the next sitting's agenda, on the entries ADR 0012 called the register's strongest evidence because they are the only origin yielding a contemporaneous date.

**The register's tier-facing job is to be a write target, not a read surface.** That is a different answer from all four candidates and it predicts a different shape.

## A write target does not need residency: the no-match read

The appending agent needs the register's words available **at the moment of a no-match** — a moment at which it has already missed the index and is already doing extra work. Nothing requires those bytes to be resident for every unrelated question anyone ever asks.

So the register is **off-tier, opened on a miss**. This is a third access mode alongside the two the design already has, and it is named — the **no-match read** — because Phase 2 has to wire it and ADR 0012 named unwired reading as this artifact's second single point of failure. An access mode nobody can state is a wiring instruction nobody can follow.

| | What | When it is read |
|---|---|---|
| Stance index | routing lines + description control | always |
| Position file | one position | retrieved by question, on an index match |
| Open-questions register | open questions + quarantined dispositions | **no-match read** — opened on a miss, to check and append |

This is **not** the ticket's fourth candidate. That one says the register is a sitting-time artifact read by `/to-stance` and nobody else; this says it is read by the agent that just missed, which is the only consumer for whom it was ever actionable. The ticket asked what the register's relation to the always-loaded tier is. The answer is **adjacency, not membership**.

**The ordering of the argument matters and should not be lost.** Byte pressure is the presenting symptom — the prototype measured the coverage statement outgrowing the routing table, and the growth is real: a position emits a routing line *and* at least one open register entry, while closure requires a later episode, so the open set grows at least 1:1 with positions and strictly faster once `asked` and `observed` are counted. But the register goes off-tier because it is mostly quarantined material, not because of byte pressure. A future reader who finds the byte argument weak should not conclude the decision weakens with it.

## Conflict class is carried, and the fitness derivation is scoped away from it

ADR 0012 refused a declared fitness statement by making record competence **derived** — the set of conflict classes present *is* the statement of what class of decision the record is competent for — and moved conflict class onto the routing line so the derivation would not quietly mean "stored twice."

A register entry is a class the record is demonstrably **not** competent for. Register entries **do** carry conflict class, because the altitude test already establishes the trade-off axis and the class is the natural agenda-sorting key for a sitting — but the derivation is defined over **routing lines only**, and that scoping is stated here rather than left to be inferred. Under the no-match read it is nearly free anyway: off-tier entries are not in the derivation's line of sight by construction, which makes an invariant structural instead of a rule someone has to remember.

## Wording length is reach, so a routing line cannot be compressed

[ADR 0013](0013-routing-line-extent-is-fixed-revision-is-a-wording-act.md) holds that a routing line's **extent is fixed by the record and only the wording is authored**, which reads as though wording were free within a fixed extent. It is not, and ADR 0013 does not say so. Findability is lexical and unranked, so the words present are the entire discoverability surface: cut words from a line and you cut the queries it matches.

**Wording length and reach are the same quantity.** ADR 0013's floor and ceiling therefore constrain the wording from both sides at once — reach the whole evidenced scope, reach no further — and there is no slack. A shorter line is a narrower line, which is a floor breach in the only currency that matters: evidenced material left unreachable while the record shows nothing. It is the same failure ADR 0013 named when it found P101's rejected draft already in breach before P102 arrived, arriving from the opposite direction.

## The tripwire's trip action is an escalation, and no automatic action is available

ADR 0012 adopted the 25KB tripwire on the condition that a tripwire whose trip action is unspecified is decoration, and parked the action here because the sheddable mass was "what is not routing lines." **This decision moves that mass off-tier entirely.** What remains is routing lines — which the section above says cannot be compressed and ADR 0013's floor says cannot be dropped — plus a constant-size description-control block. Nothing in the tier can shed.

**There is no shed action, and that is the answer rather than a failure to find one.** Any automatic action would have to shorten or drop a routing line, manufacturing exactly the false silence ADR 0013's floor exists to prevent, and degrading retrievability precisely when the record is at its largest. An automatic trip action here would be worse than decoration; it would be a bug.

The tripwire fires as an **escalation to the human at the next sitting**: the two-tier design's premise — an index cheap enough to always load — has run out, and the decision is taken then, with decades of accumulated record in view, rather than now with none. That satisfies ADR 0012's condition without pretending the action is mechanical, and it is the same shape as ADR 0011's conditional go: a falsifiable condition on the design, handed to Phase 2 as a checkpoint. **ADR 0012's parked condition therefore resolves by dissolving its premise rather than by answering it as posed** — the sheddable mass it was counting on is no longer in the tier.

## An empty routing table is a record state, not a defect

Under this decision a seed record's always-loaded tier is a description-control block and an empty routing table. The prototype instead carried a prose coverage statement — *"This record holds no positions... A reader arriving with any dilemma will match nothing here"* — which now has no home. The worry it answers is that a zero-line index is indistinguishable from no stance record at all.

It is not, and **no coverage statement is needed**: ADR 0013 retained `covers` in the always-loaded tier, so a present-but-empty index is self-describing — described, dated, covering a stated span, routing nothing. That is a constant-size frame rather than a growing one. An empty routing table is a **record state**, the same move ADR 0012 made in treating an open register entry as legitimately open rather than as work pending.

The honest consequence is stated rather than smuggled. ADR 0011 holds that the register is the seed sitting's entire deliverable; under this decision the seed record delivers **no read value at all** to a downstream reader. What it delivers is capture value — an empty routing table plus a primed register means every downstream question is a no-match against a live capture channel, which is the mechanism that produced the prototype's only contemporaneous episode. Capture value is not read value, and this does not rescue the seed record for a reader. It is the same rule at t0 and at steady state, with no special case, and it leaves Fagerlin & Schneider's unmitigated first condition exactly where ADR 0011 left it.

**Two limits found after the fact by [to-stance research: what does unranked lexical retrieval do when two routing lines match? (#118)](https://github.com/98kb/skills/issues/118), on first-party agent documentation. Neither overturns a decision above; both change what one of them means.**

**The harness performs the shed this ADR says is unavailable, and does it worst-first.** The argument above is that no automatic trip action exists which would not breach ADR 0013's floor, so the tripwire must escalate to a human. That holds as a statement about what the *design* may do. It is not a statement about what happens: Claude Code shortens descriptions to fit a listing budget *"which can strip the keywords Claude needs to match your request,"* and on overflow *"drops descriptions starting with the skills you invoke least."* A frequency-ordered drop deletes the **rarest** routing lines first — and on a stance record the position consulted once in three years is the one a reader is least able to improvise around, so the harness sheds in precisely the reverse of the order the record would choose. The escalation becomes **more** warranted, not less. What changes is the tripwire's meaning: it is not a soft boundary before which nothing happens, it is the point past which the always-loaded tier is being silently truncated on a key the record does not control and cannot observe. Recorded here rather than acted on, because the remedy is wiring in someone else's repo — the second single point of failure this map has already named twice.

**"Wording length and reach are the same quantity" does not cover the additive case.** The section above is stated without qualification, and one first-party remedy falls outside it: a **negative trigger naming a neighbour** (*"Do NOT use for simple data exploration (use data-viz skill instead)"*) adds words while subtracting reach. The uncompressibility finding is unaffected — a line still cannot be shortened without narrowing — but the converse does not hold, and the ADR should not be read as saying every addition widens. Whether that clause has a place in a routing line is [Two routing lines bear on one question (#116)](https://github.com/98kb/skills/issues/116)'s, and it is not free there either: its effect is measured per description rather than specified, and it makes one position's line name another — a cross-line dependency [ADR 0013](0013-routing-line-extent-is-fixed-revision-is-a-wording-act.md)'s per-line check cannot see.

Read it as *handed forward as a checkpoint to whichever map first has positions in the always-loaded tier*; the escalation and the condition stand.
